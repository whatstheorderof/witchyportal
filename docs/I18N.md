# Languages

Visitors can read the site in English (default), Spanish, Simplified Chinese, Hindi, French, Arabic and Portuguese.

## How it works

- **The URL holds the language.** English has no prefix (`/about`). Other languages do: `/es/about`, `/zh/retreats/…`, `/ar/contact`. `src/proxy.ts` removes the prefix, sets the `x-witchy-locale` header and serves the same page. `/en/…` redirects to the address without a prefix. Admin and API routes never take a prefix.
- **Choosing a language.** A globe picker sits in the header, a list sits in the footer, and a section sits in the phone's "More" sheet. The visitor's choice is saved in the `witchy_lang` cookie, so later visits to unprefixed pages go to their language. `?lang=en` resets the choice to English. Visitors who have made no choice get one banner suggesting their browser's language.
- **Arabic** is laid out right to left (`<html dir="rtl">`). Components use logical Tailwind classes (`ms-`, `pe-`, `start-`…), and arrow icons flip.
- **Fonts.** Arabic, Hindi and Chinese use Noto Naskh Arabic, Noto Sans Devanagari and Noto Sans SC. These are applied with `:lang()` rules in `globals.css`.
- **SEO.** Translated pages (`TRANSLATED_PATHS` in `src/i18n/config.ts`) have a canonical URL in their own language and hreflang alternates. Other pages keep the English canonical URL and show a short notice that they aren't translated yet.

## Where translations live

Translations are looked up by the English text itself:

| File | What | Used via |
|---|---|---|
| `src/i18n/ui/{lang}.json` | Interface text: menus, buttons, forms, labels, emails to visitors | `t("…")` (server: `getI18n()`, client: `useI18n()`), `msg("…")` marks constant lists |
| `src/i18n/content/{lang}.json` | Content: published retreats, departures and options, FAQs, highlights, policy pages, Home/About/Contact settings, `content/services.ts`, socials, testimonial captions | `tc(text)` |

A missing translation falls back to English. Placeholders like `{name}` must stay in the translated text. The `tests/i18n.test.ts` test checks this.

## When content changes

Text that Yulia edits in **Admin** shows in English for other languages until it's translated. To find what's missing:

```bash
npx tsx scripts/i18n-extract.ts             # summary per language (needs DATABASE_URL for DB content)
npx tsx scripts/i18n-extract.ts --out tmp/  # writes tmp/ui.json and tmp/content.json (English strings still missing)
npx tsx scripts/i18n-extract.ts --prune     # drops translations whose English no longer exists
```

Translate the strings in those files (for example, ask Claude). Add each one to the matching `{lang}.json` as `"English": "Translation"`, then commit. Run it against the **production** database so that live content is covered.

When you add interface text to the code, wrap it in `t("…")` and run the extractor.

## Not translated (Phase 2)

These sections show translated menus and labels, but their readings stay in English and are marked `lang="en"`:

- horoscopes, birth chart and synastry readings
- tarot, moon and astrology pages
- articles and tips
- the Ask a Witch videos

Testimonials stay in the client's own words.

## Review

The translations were written with AI. They aim for natural, inclusive, gender-neutral wording; the retreats themselves are described as for women. Ask a native speaker to read each language before launch. The highest priority is the booking pages, the policies and the confirmation emails.
